What you get

The tenth agent costs the same as the first.

Worktree per session

Own git worktree, own branch. Ten agents, ten checkouts, one repo. The shared path is opt-in.

tmux, in the browser

Attaches to the live pane. Scrollback, keys, clickable links, on a phone.

Nothing dies with your shell

The daemon owns the tmux sessions. Close the lid, drop SSH, reboot — they come back with the transcript.

Telegram & voice

Bind a chat or topic with /watch, talk to the agent from your phone. Voice notes transcribe with a provider key.

Your CLIs, unchanged

Same binary you type, your auth, your model config. One spawn, wake and send across all four.

Sidecars

Dev servers and compose stacks on reserved ports. They start and die with the session.

Wake & subscribe

wake --in 30m, or every morning at 09:00. subscribe pings you the moment another session hits needs_input.

Rate-limit failover

Store several Claude logins. A rate-limited session swaps credentials in place. No kill, no relaunch.

Never leaves your machine

Daemon binds to loopback. spur init opens it to your tailnet, nothing else. Your hardware, your subscriptions.

CLI

Spawn, wake, message and audit from the shell.

# start an agent on its own worktree
$ spur spawn backend-api "Fix flaky auth test" --agent claude --model opus --worktree

# see the fleet
$ spur list

# talk to a running one
$ spur send ses_123 "rebase on main and push"

# queue a message for later, or on a schedule
$ spur wake ses_123 --in 30m "check CI"

# get pinged when another session stalls
$ spur subscribe ses_123 --state needs_input --message "target needs a decision"

# check the host
$ spur doctor
Install

You don't install it. Your agent does.

No package manager to reason about, no unit files to write. Paste one prompt into a coding agent you already have and let it read the guide.

Read https://raw.githubusercontent.com/ashugaev/spur/main/docs/install-from-npm.md and install and run Spur on this machine end to end, following the guide. Do the steps yourself; don't ask me to run what you can run.
What it will do
  • Install @shugaev/spur under ~/.local
  • Run spur init — daemon on 4310, web UI on 5555
  • Register both as systemd user services
  • Put the UI on your tailnet, not a public interface
Before you start
  • Ubuntu, bare metal or a VM. This is the tested target
  • macOS and Windows: partial, expect to sort out host differences
  • Node 20+, tmux and git on the box
  • Your agent CLIs installed and already logged in

Rather do it by hand? Read the same guide yourself.

FAQ

Before you install.

Which agents does Spur run?+
claude, codex, cursor, opencode. Each gets its own tmux session and a default model from config.
Do I have to change how I use my agents?+
No. Same binary, your auth, your model config, in a real tmux pane. Stop the daemon and you are left with ordinary git worktrees.
Which operating systems work?+
Ubuntu is the tested target, bare metal or a VM; verified on 24.04 with 2 GB RAM. macOS and Windows are partial — expect to sort out host differences yourself.
Do parallel agents step on each other?+
No. A session owns a git worktree and branch — ten agents, ten checkouts. The shared project path is opt-in.
Can I use it from my phone?+
Yes. The dashboard is mobile-first, the terminal takes touch input, and Telegram spawns sessions and relays text and voice.
What can trigger an agent automatically?+
Seven pollers: cron, GitHub, GitHub CI, GitLab, Sentry, systemd service logs, Telegram. A trigger spawns a session or sends a message into a live one.
Does my code leave the box?+
Only where your agent already sends it. Spur itself is a local daemon on loopback; spur init opens the UI to your tailnet. There is no Spur cloud, no account, no seat.

Sources & triggers

Something happens. An agent is already on it.

You write the rule once in spur.yaml. After that nobody has to be awake.

What you get

The tenth agent costs the same as the first.

Worktree per session

Own git worktree, own branch. Ten agents, ten checkouts, one repo. The shared path is opt-in.

tmux, in the browser

Attaches to the live pane. Scrollback, keys, clickable links, on a phone.

Nothing dies with your shell

The daemon owns the tmux sessions. Close the lid, drop SSH, reboot — they come back with their transcript.

Telegram & voice

Bind a chat or forum topic with /watch, then talk to the agent from your phone. Voice notes transcribe once you set a provider key.

Four agents, one API

Same spawn, wake, send and dashboard across claude, codex, cursor and opencode. Model set per session.

Sidecars

Dev servers and compose stacks on reserved ports. They start and die with the session.

Wake & subscribe

wake --in 30m, or every morning at 09:00. subscribe pings you the moment another session hits needs_input.

Rate-limit failover

Store several Claude logins. A rate-limited session swaps credentials in place. No kill, no relaunch.

Never leaves your machine

Daemon binds to loopback. spur init opens it to your tailnet, nothing else. Your hardware, your agent subscriptions, no seats.

CLI

Spawn, wake, message and audit from the shell.

# start an agent on its own worktree
$ spur spawn backend-api "Fix flaky auth test" --agent claude --model opus --worktree

# see the fleet
$ spur list

# talk to a running one
$ spur send ses_123 "rebase on main and push"

# queue a message for later, or on a schedule
$ spur wake ses_123 --in 30m "check CI"

# get pinged when another session stalls
$ spur subscribe ses_123 --state needs_input --message "target needs a decision"

# check the host
$ spur doctor
FAQ

Before you install.

Which agents does Spur run?+
claude, codex, cursor, opencode. Each gets its own tmux session and a default model from config.
What do I need on the host?+
A Linux box you control, Node 20+, tmux, git, and the agent CLIs installed and logged in. Daemon and web UI install as systemd user services. Verified on Ubuntu 24.04, 2 GB RAM.
Do parallel agents step on each other?+
No. A session owns a git worktree and branch — ten agents, ten checkouts. The shared project path is opt-in.
Can I use it from my phone?+
Yes. The dashboard is mobile-first, the terminal takes touch input, and Telegram spawns sessions and relays text and voice.
What can trigger an agent automatically?+
Seven pollers: cron, GitHub, GitHub CI, GitLab, Sentry, systemd service logs, Telegram. A trigger spawns a session or sends a message into a live one.
Does my code leave the box?+
Only where your agent already sends it. Spur itself is a local daemon on loopback; spur init opens the UI to your tailnet. There is no Spur cloud, no account, no seat.

Stop babysitting one terminal.

Hand the install prompt to a coding agent and let it do the whole thing. Tested on Ubuntu; elsewhere expect to sort out host differences.

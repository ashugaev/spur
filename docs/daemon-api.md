# Daemon HTTP API

- `GET /info` — `lifecycleInstanceId`, runtime `buildId`: process/build identity; `v2/src/session-lifecycle.ts`, `v2/src/build-identity.ts`.
- `GET /headroom`
- `GET /usage` — quota windows per Claude account and Codex (one row per ready OAuth managed account from the cached quota, `pending` error row until cached; the host login row is hidden when the provider has a ready managed account, or a managed account in any state has the same email, and the same organization/account id when both have one, read from `~/.claude.json` `oauthAccount` and the `~/.codex/auth.json` id_token claims; companion failure falls back to host rows), per-source error entries, token totals today/7d/30d; provider request timeout 5s; MCP `get_usage`; `v2/src/usage-report.ts`.
- `GET /models` — model and default reasoning capabilities; discovery in `v2/src/agents/models.ts`.
- `GET /api/pr-status` — web PR status, nullable reviewer names, native review requirement; `packages/web/src/app/api/pr-status/route.ts`, `packages/web/src/lib/pr-status-shape.ts`.
- `POST /api/pr-status/batch` — web PR statuses, reviewer/native requirement metadata; `packages/web/src/app/api/pr-status/batch/route.ts`.
- `GET /user-actions`
- `GET /deploy/versions`
- `GET /deploy/switch/status`
- `POST /deploy/switch` — see [Auto update](configuration.md#auto-update)
- `POST /deploy/auto-update`
- `GET /claude-accounts` — `label` is the display name.
- `POST /claude-accounts/add` — body label ignored.
- `POST /claude-accounts/remove`
- `POST /claude-accounts/:id/finish-login`
- `GET /claude-accounts/:id/login-status`
- `GET /auth-accounts` — provider profiles (`identity`, `displayName`, `quota`, `quotaError` (last refresh failure kind while no quota is cached), status, `limited`, `cooldownUntil`, `credential` `oauth|api_key`) and pool preferences; `v2/src/server.ts`.
- `POST /auth-accounts` — body `{provider}`; create Claude/Codex profile; `v2/src/server.ts`.
- `DELETE /auth-accounts/:id` — remove unused profile; `v2/src/server.ts`.
- `POST /auth-accounts/:id/login` — start sign-in; body `{method?}` `oauth` (Claude default), `device` (Codex default), `browser`; other provider combinations `400`; `v2/src/server.ts`.
- `POST /auth-accounts/:id/api-key` — body `{apiKey}`; saves only after a test request succeeds; key never returned; `v2/src/server.ts`.
- `GET /auth-alerts` — `{alerts}` one per broken managed account or host login, none for a host login with the same email as a managed account of the provider (and the same organization/account id when both have one) while no live unbound session of the provider uses it; event `session.auth.failed` once per breakage; `v2/src/auth-alerts.ts`.
- `POST /auth-terminal-logins` — body `{accountId}` or `{host:"claude"|"codex"}`; native CLI sign-in in tmux; repeat restarts; response carries `command`, the display string of the native login command; `v2/src/auth-terminal-login.ts`.
- `GET /auth-terminal-logins/:id` — status `running|verifying|ready|not_signed_in`, `reason` (`duplicate` when the account is already saved), `command`; `404` unknown; `v2/src/auth-terminal-login.ts`.
- `DELETE /auth-terminal-logins/:id` — stop and delete the throwaway home; `v2/src/auth-terminal-login.ts`.
- `POST /auth-accounts/:id/login-input` — submit code or cancel; `v2/src/server.ts`.
- `GET /auth-accounts/:id/login-status` — durable OAuth readiness; `v2/src/server.ts`.
- `PATCH /auth-pools/:provider` — default account and quota rotation; creates a missing pool; `v2/src/server.ts`.
- `GET /projects`
- `GET /projects/cron?project=<id>` — cron sources, bound triggers, owner-file drift, last tick/action from the live event log; `project` optional; `404` unknown project; `v2/src/cron-jobs.ts`.
- `GET /projects/cron/edit` — disk draft for a Cron spawn trigger; MCP `get_cron_job_draft`; `v2/src/cron-job-editor.ts`.
- `PATCH /projects/cron/edit` — save validated YAML with revision conflict detection, then reload automation; `activation` applied|failed; MCP `save_cron_job_draft`; `v2/src/cron-job-editor.ts`.
- `POST /projects`
- `PATCH /projects/:id`
- `DELETE /projects/:id`
- `POST /projects/connect`
- `POST /projects/disconnect`
- `GET /backlog/available`
- `GET /projects/:id/slash-commands`
- `GET /projects/:id/spawn-defaults?agent=<name>` — `{model, reasoningEffort, worktree}`; unset effort is `null`.
- `GET /projects/:id/branches/exists?name=<branch>`
- `POST /projects/:id/preflight-batches`
- `POST /projects/:id/preflight` — same `409` as `POST /sessions/background` when `preflightBatchId` is already claimed.

## Session routes

- `GET /sessions` — array; `includeCompleted=1|true` adds completed; repeated `link=<label[=URL]>` uses AND (`label`: any URL, `URL`: normalized; invalid: 400); optional `rateLimitResetAt` ISO UTC, unknown omitted/cleared on limit exit; attention entry/exit immediate on fresh classification across GET/list, working/waiting hold retained; `sidecars[].url` ready endpoint, `sidecars[].ports[].listening` host TCP listener true|false|null; `x-spur-lifecycle-instance-id` header, per-row `lifecycle`; `v2/src/server.ts`, `v2/src/session-lifecycle.ts`; no `503` on lifecycle churn, moving row carries last build and receipt.
- `GET /sessions/transitions` — event-time S5 links, repeated `link` AND; OR: poll unfiltered and filter `entry.links`, or poll each link filter with its own cursor; default: all status edges (completed/killed/errored/stopped/park/resume), attention-state entry/reset/exit (needs_input/rate_limited/stale/stopped/error/killed); exclusive restart-safe `since`, `limit` default 200 (1..1000), optional `kinds=status,state`; invalid cursor 400, expired 410/full-list resync, refresh failure 500; hot + five uncompressed 16 MiB segments, no time guarantee; `v2/src/server.ts`, `v2/src/session-transitions.ts`.
- `POST /sessions` — `201` accepted spawning identity under [admission pressure](configuration.md#admission-control); optional `allowedTriggers` (omitted = all sends, `[]` = none; carried by respawn/handoff), `reasoningEffort`, `prAlertOwner` (default `false`, [exclusive PR alerts](configuration.md#pr-alert-ownership)); writable `reuseWorkspaceSessionId` [closeout take](commands.md#session-tools-and-environment); `400 pr_alert_owner_invalid`, `409 pr_alert_owner_conflict` body `{ code, error }`; optional `idempotencyKey` (1-128 chars, no control characters, else `400`): same key and request returns the first session with `replayed: true`, other request or project `409 idempotency_key_conflict` body `{ code, sessionId, error }`; a conflicting call made while the first is still running waits for it, then is answered as if sent after it; a key whose spawn left an errored record keeps returning that record, retry with a new key; keys are global and live as long as the session record, forgotten once `spur gc` archives it; `v2/src/session-service.ts`, `v2/src/pr-alert-owner.ts`.
- `POST /sessions/background` — `201` accepted spawning identity before [resource recovery](configuration.md#admission-control); same allowlist, PR-alert, closeout-take and `idempotencyKey` contracts as `POST /sessions`; `409 spawn_in_progress|spawn_committed|spawn_failed` body `{ code, sessionId, error }` for claimed `preflightBatchId`; `v2/src/session-service.ts`.
- `POST /shepherd/spawn`
- `POST /sidecars/sweep` — body `{ reap?: boolean }`, default `false`. Always `200`. Response `{ supported, leaked, reaped }`: `supported` is `false` when the process table or procfs is unreadable, in which case `leaked` and `reaped` are both `[]`. Each `leaked` row carries `kind: "worktree-tree" | "orphan-daemon"`; a `worktree-tree` row's `reapable` reflects proven Spur provenance and carries `rootPid`, `pgid`, `ageSeconds`, `worktreePath`, `args`, `sidecarName`, `tree` (descendant pids, root first), `treeRssKb`; an `orphan-daemon` row is always `reapable: false` and carries `configPath`/`cliEntryPath` instead of a `sidecarName`, plus `port: number | null` and `liveness: "serving" | "not-serving" | "unknown"`. `reap: true` signals only `reapable` rows — never an `orphan-daemon` row, serving or not — and populates `reaped`, one entry per `reapable` leaked tree it signaled: `{ sessionName, panePid, survivors, blindKill }` — `survivors` is the pids still alive after the SIGKILL confirmation window, and `blindKill` is `true` when tmux was killed with no verified process-tree signal (no pane pid, or an unusable snapshot, and no identity fallback confirmed a reap either) — a `survivors: []` alongside `blindKill: true` is not proof anything died, only that nothing was checked. See [Sidecars](commands.md#sidecars)
- `GET /sessions/:id` — current row, `sidecars[].url` ready endpoint, `sidecars[].ports[].listening` host TCP listener true|false|null; Cursor `queuedMessageTyped.ackBaseline.deliveryId` optional UUIDv4, correlated `file:null` requires `size:0` and valid ID, malformed IDs drop baseline, legacy string-file floors retained; optional read-only `intervalWake.dispatchClaimId`: opaque correlation, absent on legacy records, ignored on input; `v2/src/types.ts`, `v2/src/metadata.ts`; ephemeral `lifecycle` receipt; `v2/src/session-lifecycle.ts`.
- `GET /sessions/:id/slash-commands`
- `GET /sessions/:id/conversation` — optional `view=messages&limit=<1..100>` (default 50): bounded visible-message page; `v2/src/server.ts`, `v2/src/conversation-page.ts`; omit view for legacy response.
- `GET /sessions/:id/user-actions`
- `GET /sessions/:id/subscriptions`
- `GET /sessions/:id/logs` — `scope=runtime|sidecar|service|all`, `name`, `limit` (default 200 globally); retained pane and archived rows; existing session record and `limit>0`: 404 for named no-pane/no-archive or outputless stopped service, 502 for failed capture; absent record: archived rows (200); `v2/src/server.ts`.
- `POST /sessions/:id/send` — `{message,queue:false,interrupt:true}` interrupts active work; interrupt ignored without `queue:false`; repeats within 5 seconds queue at tail; explicit interrupt response `sendOutcome`: `{kind:"sent",interrupted:boolean}` or `{kind:"queued",reason:"interrupt_guard"|"no_interrupt"}`; `no_interrupt` retains `queuedAheadReason:"no_interrupt"` for head queue — `v2/src/session-service.ts`, `v2/src/daemon-contracts.ts`.
- `POST /sessions/:id/source-poll-enable` — `{}`. Clears durable poll-disable registry (every file under the project, incl. removed sources) + live in-process gate per `github` source; `200 { ok, sessionId, projectId, cleared: { sourceId, prNumber }[] }`; `cleared: []` no-op; `404` unknown session. See [source](commands.md#source)
- `POST /sessions/:id/answer`
- `POST /sessions/:id/launch/submit` — presses submit over a pending `submitUnconfirmedAt` prompt
- `POST /sessions/:id/submit-failed/retry` — re-queues `submitFailedMessage` at the head
- `POST /sessions/:id/submit-failed/dismiss` — drops `submitFailedMessage`
- `POST /sessions/:id/source-reply`: `requestInterfaceApproval` semantic proposal; `images` `{name,data}[]` base64, invalid -> 400 before any send; body cap 15 MB; response `images` count; `v2/src/session-service.ts`.
- `GET /sessions/:id/source-info` — read-only association and cached bot identity; `v2/src/server.ts`, `v2/src/session-service.ts`.
- `POST /sessions/:id/opened`
- `POST /sessions/:id/pause`
- `POST /sessions/:id/rate-limit/clear` — rejects MCP origin and caller-session header; optional `force`; `v2/src/server.ts`.
- `POST /sessions/:id/complete` — closes session; response adds `closeout: {unverified}` (desk: summed) when archives listed unverified files; optional correlation `operationId`, group `completedIds`/outcomes, lifecycle 409/503, agent `409 work_snapshot_required`; `v2/src/session-lifecycle.ts`, `v2/src/server.ts`.
- `POST /sessions/:id/self-destruct` — `409 work_snapshot_required`
- `POST /sessions/:id/kill`
- `POST /sessions/:id/restore` — optional `operationId`; `restart` defaults false, replaces running terminal; settled receipt, lifecycle 409/503, 20-minute deadline 504, disconnect cancellation; `v2/src/server.ts`.
- `POST /sessions/:id/reopen` — restore request fields and single reopen receipt; `v2/src/session-lifecycle.ts`, `v2/src/server.ts`.
- `POST /sessions/:id/handoff` — caller from `x-spur-caller-session` (agent actor, may name another session), none = human; `403 handoff_target_not_stalled` body `{ code, sessionId, status, error }`; agent self-handoff `409 todo_ledger_empty`, `409 work_snapshot_required` (running source without rate-limit/server-error marker only); response adds `movedTodoItems`; `reasoningEffort`: omitted carries same-agent override, agent switch drops it, `null` uses project default; optional `idempotencyKey` (same format, scoped to the source): retry after success `200` successor view + `movedTodoItems` + `replayed: true`, other request `409 idempotency_key_conflict` with successor `sessionId`, same key while running waits for that result, other or no key on a completed source keeps the existing error; a handoff that fails after its successor started leaves the successor running and the source open with no stored key, a same-key retry starts another successor (check `spur list` first); `v2/src/session-service.ts`.
- `POST /sessions/:id/respawn` — `reasoningEffort`: omitted carries same-agent override, agent switch drops it, `null` uses project default; `v2/src/session-service.ts`.
- `POST /sessions/:id/switch-auth` — next-request managed account or Auto; a claude/codex session without `auth` is bound and, when running, relaunched with resume (`409` while working unless `force: true`, `409` with no recorded conversation id, `409` when the relaunch cannot resume (session left `stopped` with stopReason `auth_switch_unresumable` on its previous account), `400` with no ready account or a codex custom provider, binding rolled back on failure); `v2/src/server.ts`.
- `GET /sessions/:id/todo` — archived too; `404` without a ledger
- `POST /sessions/:id/todo` — `409 todo_ledger_empty|todo_open_work|todo_transition_conflict`. See [todo](commands.md#todo-snapshot)
- `GET /sessions/:id/snapshots` — metadata; `order=asc|desc` (default asc), `limit` 1..100, exclusive `before`/`after` versions; archived too; `400 invalid_snapshot_request|404|500 snapshot_corrupt`; `v2/src/snapshots.ts`
- `POST /sessions/:id/snapshots` — `{content, final?}`; caller header, when set, must equal `:id`; `400|404|409 snapshot_conflict|413 snapshot_too_large`. See [snapshot](commands.md#todo-snapshot)
- `GET /sessions/:id/snapshots/:version` — positive integer or `latest`; adds `freshness`; `includeDone=1` adds `done`; archived too, no wake; `400|404|500 snapshot_corrupt|500 todo_ledger_corrupt`. See [snapshots](snapshots.md#read)
- `GET /snapshots/latest` — repeatable `link=label[=url]` (required, AND), `includeDone=1`; per matching session incl. completed, archived; `400 invalid_snapshot_request`, `500 snapshot_corrupt`. See [snapshots](snapshots.md#read)
- `GET /sessions/:id/closeout` — manifest + `versions`; latest, or `?version=<n>`; live, completed, archived; `404` none or unknown version, `400` bad version, `500 closeout_corrupt`; `v2/src/closeout-archive.ts`

- `GET /closeouts` — repeatable `link=label[=url]` (required, AND), else `400`; latest version per session. See [closeout](commands.md#todo-snapshot)
